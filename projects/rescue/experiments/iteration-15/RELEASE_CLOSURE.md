## Scope discipline
- No additional standalone components or speculative enhancements unless tied to a failed acceptance gate.
- One consolidated release source tree/candidate, not every historical simulation variant. Preserve previous evidence. Reuse pinned upstream source/licenses; no relicensing. No commits/pushes until owner approves coherent milestone.
- Proposed engineering target <=52 KiB BIOS (53,248 bytes), 12 KiB reserve; hard configured limit 64 KiB. At current simulation size 7,244 bytes to engineering target. Budget measured on actual release link map after removing simulation fixtures. No ROM expansion without review of BRAM resources and timing. Measure stack/BRAM and external configuration image size independently. If over budget, reduce diagnostic strings/console and duplicated helpers, prefer host-side optional processing, keep safety checks. Do not remove hash, bounds, journal safety, identity protection or recovery to fit. No assurance all remaining release requirements fit until integrated link.
- Defer separate operation ledger integration, extra protocol versions, elaborate wear-leveling, multi-client refinements beyond bounded safe transactions, authentication profiles/TLS and optional watchdog until basic board proof. Preserve the specification's mandatory safety, replay/idempotency, discovery and acceptance requirements; use a lean implementation or explicitly document unmet gates before any v1 acceptance. Do not treat the provisional UDP format as final API.
- First milestone = board-qualified read-only diagnostic, not full v1. Next milestone = one real verified A/B application update, trial, return, confirm and rollback with independently proven recovery, not just another simulation.

## Finite sequence and stop rules
1. Freeze diagnostic image and evidence (done); prepare exact device-specific read-only identification/entry and recovery proposal. No physical access absent explicit separate approval. If reversible stock entry unproven, investigate stock source and recovery path only; stop if ambiguous.
2. With separate owner approval, establish observed revision/JEDEC/factory identity/boot constraints and reversible Rescue startup; preserve factory bytes privately before any erase; confirm unique MAC and Ethernet/clock/button. Do not overwrite permanent boot selection. Record S2/B3 evidence or blocker.
3. Once geometry and entry proven, consolidate only existing essential firmware: upstream BIOS minimal init, identity, protected partition map, bounded image transfer/verify, redundant journal, trial/rollback, ICAP/ownership, host status/discovery and bounded autoboot. Keep simulation storage and fake addresses out of actual build. Measure exact linked size, reproduce ISE timing and check configuration image format/slot sizes. Physical write adapter remains an unresolved engineering and authorization gate; do not bypass controls.
4. With exact separate approval and verified fallback, exercise one controlled persistent update and trial against an actual board and representative app. Prove Rescue-first cold boot and held-button recovery even with nonresponsive app, interrupted upload preservation, failed-trial rollback, confirmed app after reset. Record acceptance evidence. Only activate permanent policy after independent recovery proof, per spec §8.
5. Finish required trusted-LAN discovery, API and host workflow; qualify remaining applicable Q01–Q25 per spec, including reproducibility and multi-board requirements where applicable. Publish precise limitations for unqualified profiles/features. One coherent release review, then owner-approved Git promotion. No claim of full v1 before gates met.

Each iteration must close a named acceptance gate or state a specific blocker. No new feature backlog by default. Current stop: S0/S1 diagnostic evidence; S2 not started. Physical work must be individually authorized. This turn changed only this local closure record, not source, builds, services, Git, or hardware.
