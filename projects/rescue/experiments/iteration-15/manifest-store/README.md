# Proposed durable per-slot manifest record

This component is tested on simulated NOR only. It assumes a dedicated independent metadata erase unit per application slot, separate from raw configuration bytes. The allocation and capacity impact must be approved against actual JEDEC geometry and the final board partition map before integration. The caller exclusively owns the slot, invalidates its old manifest before modifying image bytes, verifies complete raw-image readback against the exact canonical manifest, and only then publishes. A committed manifest never substitutes for a fresh raw image hash and boot authorization. The physical callback must split programs across pages and confirm operation completion; no physical backend is present.

Record: marker byte (erased FF, committed 00), PLM1 magic, two-byte big-endian manifest length, 32-byte manifest SHA256, canonical CBOR. Body is read back before final marker write. The read path validates bounds, canonical parser and digest. On failure outputs remain unchanged. Native tests include interruption and corruption; RV32 compile and relocatable link check no unresolved symbols. This is not yet wired into flash staging or the BIOS.
