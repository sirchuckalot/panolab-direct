# Provisional simulation-only management datagram format

This is an internal integration fixture, not a deployed network API or a finalized replacement for the Rescue v1.1 versioned resource contract. No sockets, physical writes, authorization, discovery or boot commands. Trusted-LAN must remain isolated and unpaired status explicit in any eventual service.

Header (8 bytes): version 1, operation byte, big-endian body length u16, request correlation ID u32. Body max 1200 bytes. BEGIN (1): operation ID u32, expected journal sequence u32, manifest length u16, canonical CBOR bytes (1..1024). CHUNK (2): operation ID u32, relative image offset u32, chunk length u16, bytes (1..1024). SEAL (3) and CANCEL (4): operation ID u32. STATUS (5): no body. No absolute flash address, slot address, raw bus command or launch endpoint. Server selects target through trusted configuration. Exact lengths required. Response is 16 bytes: echoed header version/op/id with body length 8, reserved zero, code, state, offset-present flag, next offset u32. Codes and states in management_wire.h. A conflict can report current offset; replay or unknown ID is rejected. Operation IDs are 32-bit in this prototype, not the full 64-bit underlying sequence space. Manifest limit is narrower than the parser's 2048-byte maximum. Status lacks durable operation identity. Final API must handle reset/expiry, ambiguous responses, session ownership, retry semantics, rate limiting and identity/authorization. Never expose this fixture to a real network.
